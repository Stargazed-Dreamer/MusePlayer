# 文档洁癖 (neat-freak)

## 触发词
同步一下、整理文档、整理一下、收尾、/sync

## 概述
会话结束后对项目文档进行系统性审查与同步，确保代码和文档始终一致。核心哲学：你是知识编辑，不是知识记录仪。

## 前置条件
- 本会话中对项目代码或文档做过修改

## 工作流

### 1. 扫描变更

回顾本会话的所有操作：
- 新增/修改/删除了哪些文件？
- 发现了什么新的知识（踩坑、约束、陷阱）？
- 是否有新的可重复执行的任务？

### 2. 审查 AGENTS.md

逐项检查：
- **项目简介**：是否需要更新？
- **技术栈**：是否新增/升级了依赖？
- **关键约束**：是否发现了新的坑？已有的约束是否仍然准确？
- **API 常见陷阱**：是否发现了新的陷阱？
- **项目结构**：是否新增/删除/重命名了目录或文件？

### 3. 审查 Skill 文件

对每个受影响的 Skill：
- **触发词**：是否需要新增触发词？
- **工作流**：步骤是否仍然准确？
- **依赖**：是否有新增/变更的依赖？
- **关键规则**：是否需要补充新规则？

### 4. 审查 _index.md

- Skill 列表是否与实际文件一致？
- 触发词是否与各 Skill 文件中的定义一致？

### 5. 审查测试

- 新增功能是否有对应的验证方式？
- 现有验证方式是否仍然有效？

### 6. 审查配置

- `.trae/rules/project_rules.md` 检查清单是否需要更新？
- `.gitignore` 是否需要新增排除项？

## 关键规则

### 同步矩阵

| 修改了 | 必须同步检查 |
|--------|-------------|
| `.agents/skills/xxx.md` | `_index.md` |
| 核心代码文件（新模块） | `AGENTS.md` 项目结构、`_index.md` |
| 核心代码文件（改接口） | 对应 Skill、`_index.md` |
| `app/runtime/control_server.py` | `player-control.md`、`library-manage.md` |
| `app/services/app_controller.py` dispatch_command | 所有涉及 TCP 命令的 Skill |

### 做与不做

**做**：
- 删除过时信息
- 更新变化信息
- 合并重复信息
- 补充缺失信息

**不做**：
- 重写文档
- 添加注释
- 创建新文档（除非确实需要）
- 记录临时状态
- 修改代码逻辑

## 依赖

| 依赖 | 路径/接口 | 说明 |
|------|----------|------|
| AGENTS.md | 项目根目录 | 项目入口文档 |
| _index.md | `.agents/skills/_index.md` | Skill 索引 |
| project_rules.md | `.trae/rules/project_rules.md` | 变更检查清单 |

## 输入/输出
- 输入：本会话的变更记录
- 输出：更新后的文档文件列表
